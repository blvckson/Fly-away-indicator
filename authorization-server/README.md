# Fly Away authorization service

This service is required for production authorization. The Android apps intentionally fail closed if no HTTPS service URL is configured.

## Deployment
Deploy this directory as a Node.js web service on a host that supports persistent storage. Set the secret environment variable `ADMIN_API_KEY` to a long random secret and mount persistent storage for `DATA_FILE`. Do not commit the admin key into this repository or APK. Use HTTPS only.

Set the same service URL as Gradle property `authApiBaseUrl` when building both apps, for example:
`gradle -p admin-ai assembleDebug -PauthApiBaseUrl=https://YOUR-SERVICE-HOST`
`gradle -p customer-ai assembleDebug -PauthApiBaseUrl=https://YOUR-SERVICE-HOST`

The Admin AI app's "Admin server key" field must contain the value of `ADMIN_API_KEY`. This is separate from the optional local Admin AI passcode.

## Rules enforced by the service
- One-time activation codes are generated by Admin AI and stored as hashes.
- Codes are consumed on successful activation and cannot authorize a second installation.
- Expiry begins at activation time. The default period is 14 days and can be changed.
- Extension adds time to the current expiry; if already expired, the extension starts at the current time.
- Customer AI checks server authorization on each app opening and stays locked if the server is unreachable.
- Deactivation and expiry are enforced server-side.
- Customer records include the administrator-entered name, activation time, expiry, installation ID, and status.

Do not use a production APK until the service is deployed, HTTPS works, and end-to-end activation/revocation tests pass.
